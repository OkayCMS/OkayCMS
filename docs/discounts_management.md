# Система керування знижками

В OkayCMS реалізована централізована система керування знижками. Вона дозволяє керувати послідовністю та
пріоритетністю застосування знижок як для кошика загалом, так і для кожного окремого товару в кошику. Можна
однаково гнучко налаштовувати як стандартні знижки (купон і група користувача), так і знижки, створені модулями,
за умови, що вони використовують єдиний системний інтерфейс для реєстрації та додавання знижок у систему.

## 1. Сутність знижки

### 1.1. Види знижки

Реалізовано два базові варіанти знижки:
1)  `Абсолютна` — знижка, виражена в абсолютній грошовій величині. Ціна зі знижкою ніяк не залежить від
    порядку застосування знижок до ціни.

2) `Відсоткова` — знижка, виражена у відсотках. Ціна зі знижкою залежить від порядку застосування знижок до ціни.

### 1.2. Режими обчислення знижки

У кожної знижки є 2 режими обчислення, від яких залежить, яку ціну беруть як базу для дисконтування для конкретної
знижки:
1) `Від останньої знижки` — за базу береться ціна, яка вийшла після розрахунку всіх попередніх
   знижок.

 *Приклад 1:*
 
     Усі 3 знижки працюють у режимі `Від останньої знижки`
     Цена: 1000
     Скидка 1: 10%
     Скидка 2: 20%
     Скидка 3: 30%
     
     У скороченому вигляді розрахунок виглядає так:
     1000 - 10% - 20% - 30%; = 504
    
     Якщо розбити на етапи:
     1) 1000/100*10 = 100 - знижка 1
     2) 900/100*20 = 180 - знижка 2
     3) 720/100*30 = 216 - знижка 3
     4) 1000 - 100 - 180 - 216 = 504
     
     Підсумкова ціна: 504

2) `Від початкової ціни` — за базу береться початкова ціна.

 *Приклад 2:*
 
     Усі 3 знижки працюють у режимі `Від початкової ціни`
     Цена: 1000
     Скидка 1: 10%
     Скидка 2: 20%
     Скидка 3: 30%
     
     У скороченому вигляді розрахунок виглядає так:
     1000 - 1000/100*10 - 1000/100*20 - 1000/100*30; = 400
    
     Якщо розбити на етапи:
     1) 1000/100*10 = 100 - знижка 1
     2) 1000/100*20 = 200 - знижка 2
     3) 1000/100*30 = 300 - знижка 3
     4) 1000 - 100 - 200 - 300 = 400
     
     Підсумкова ціна: 400

**У випадку `абсолютного` виду знижки кінцева величина знижки не залежатиме від режиму обчислення.**

Можливий варіант роботи знижок із різними режимами.\
 *Приклад 3:*
 
     1 і 3 знижки працюють у режимі `Від останньої знижки`
     2 знижка працює у режимі `Від початкової ціни`
     Цена: 1000
     Скидка 1: 10%
     Скидка 2: 20%
     Скидка 3: 30%
     
     У скороченому вигляді розрахунок виглядає так:
     1000 - 1000/100*10 - 1000/100*20 - 1000/100*30; = 400
    
     Якщо розбити на етапи:
     1) 1000/100*10 = 100 - знижка 1
     2) 1000/100*20 = 200 - знижка 2
     3) 700/100*30 = 210 - знижка 3
     4) 1000 - 100 - 200 - 210 = 490
     
     Підсумкова ціна: 490

### 1.3. Назва знижки

Загальні положення:
1) Має відображати загальний зміст і тематику знижки. Бажано — не більше 1–2 слів.
2) Відображається однаково як для адміністратора, так і для користувача (у кошику та на сторінці замовлення).
3) Поле є мультимовним.

### 1.3. Опис знижки

Загальні положення:
1) Розширена інформація про знижку. Корисно, якщо логіка формування знижки допускає різні види знижок під однією
   й тією самою назвою.
2) За замовчуванням відображається лише в адмін-панелі. За потреби можна виводити на frontend.
3) Поле є мультимовним.

## 2. Відображення та робота зі знижками

### 2.1. Адмін-панель

#### 2.1.1. Керування наборами

У боковому меню виберіть пункт Замовлення → Знижки. Тут розташоване керування пріоритетами та послідовністю обчислення
знижок для товарів у кошику та для самого кошика. Ця сторінка відповідає за етап до оформлення замовлення та потрібна для того,
щоб визначити, які знижки можуть бути застосовані до замовлення користувача.

##### 2.1.1.1 Зареєстровані знаки знижок

У верхній частині сторінки розташовані всі зареєстровані знаки знижок, які поділені на 2 групи — для кошика
та для окремої позиції в кошику. Кожен знак унікальний і представляє певну знижку. Не плутайте назви
й описи, що знаходяться тут, із тими, що зрештою будуть збережені разом із застосованою в замовленні знижкою. Тут вони потрібні
лише для розуміння адміністратором, яка знижка чим є.

##### 2.1.1.2 Набори знижок

Набір знижок — це рядок зі знаків знижок у тому порядку, у якому вони мають
обчислюватися. Замість кожного знака надалі буде використовуватися конкретна знижка. Які саме властивості матиме
ця знижка, вирішує система на підставі введеної нижче інформації та інформації, наданої модулем (або, у випадку стандартних знижок, самою системою). На цьому етапі
немає можливості якось визначити тип або значення знижки — цей функціонал повністю покладено на внутрішню логіку модуля. Модуль, зі свого боку, може
надавати додатковий інтерфейс для налаштування або використовувати будь-який інший підхід.

Запис кожного знака в наборі потрібно починати з символа `$` і закінчувати пробілом (для останнього знака пробіл не
потрібен). За замовчуванням стандартний режим роботи кожної знижки в наборі — `від останньої знижки`. Після відкривального
знака `$` можна вказати спеціальний символ `<`, який змінює режим роботи знижки на `від початкової ціни`.

*Приклад 4:*

`$<ok_disc`\
Де:\
`$` — символ початку знака знижки\
`<` — символ режиму роботи `від початкової ціни`\
`ok_disc` — знак знижки\
Усе, що знаходиться між `$` (або між `<`, якщо вказано) та пробілом, буде інтерпретовано як знак знижки.

Кожен окремий набір є окремою інструкцією та під час виконання не комбінується з іншими наборами.
Завжди виконується лише той набір знижок, для якого в поточний момент доступні ВСІ зазначені знижки. Найвищий
пріоритет має верхній набір. Якщо він не відповідає умовам, використовується наступний, потім наступний тощо — до останнього,
поки не буде знайдено відповідний. Якщо жоден набір повністю не підійшов, жодна послідовність знижок не буде застосована. Для `кошика` весь цикл
пошуку відповідного набору відбувається 1 раз. Для `позицій` цей цикл повторюється для кожної позиції окремо й
незалежно від інших позицій. Чи доступні певні знижки в кожній конкретній ситуації та чи може бути виконаний
певний набір знижок, залежить від внутрішньої логіки модулів і самої системи.

*Приклад 5:*

    Дані такі набори знижок:
    1. $ok_disc1
    2. $ok_disc2
    3. $ok_disc1 $ok_disc2

    Доступні знижки:
    1. $ok_disc1
    2. $ok_disc2

    Перший набір знижок є пріоритетним і знижки, що в ньому присутні, доступні.
    Виконуватиметься саме перший набір.

`$ok_disc1 $<ok_disc2 $ok_disc3`\
Де:\
Перша знижка — `ok_disc1`, режим роботи — `від останньої знижки`\
Друга знижка — `ok_disc2`, режим роботи — `від початкової ціни`\
Третя знижка — `ok_disc3`, режим роботи — `від останньої знижки`

*Приклад 6:*

    Дано такий набір знижок:
    $ok_disc1 $<ok_disc2 $ok_disc3
    Где:
    Перша знижка — ok_disc1, режим роботи — від останньої знижки\
    Друга знижка — ok_disc2, режим роботи — від початкової ціни\
    Третя знижка — ok_disc3, режим роботи — від останньої знижки

    Значення знижок:
    ok_disc1 - 150
    ok_disc2 - 25%
    ok_disc3 - 10%
    
    Початкова ціна — 1000

    У скороченому вигляді розрахунок виглядає так:
    1000 - 150 - 1000/100*25 - 600/100*10; = 400
    
    Якщо розбити на етапи:
    1) 150 - знижка 1
    2) 1000/100*25 = 250 - знижка 2
    3) 600/100*10 = 60 - знижка 3
    4) 1000 - 150 - 250 - 60 = 540
    
    Підсумкова ціна: 540

Є можливість вказувати один знак знижки кілька разів. У такому разі знижка буде застосована так само, якби
це були 3 різні знижки. У комбінації `$ok_disc1 $ok_disc1 $ok_disc1` одна й та сама знижка буде послідовно
застосована 3 рази.

##### 2.1.1.3 Використання знаків у наборах

Усі зареєстровані знаки належать одній із двох сутностей: кошик або позиція.
Записані знаки в наборі одночасно виконують 2 функції:
1) `Перевірочна` — задає умову, за якої цей набір вважається дійсним і може бути виконаний.
2) `Виконавча` — задає послідовність застосування знижок.

Якщо в наборі для сутності використовувати лише знаки, зареєстровані для цієї ж сутності, то кожен зі знаків виконуватиме
обидві функції. Але в наборі передбачено можливість використовувати знаки, зареєстровані для іншої сутності.
У такому разі знак, записаний у набір, але такий, що належить до іншої сутності, виконуватиме лише
`перевірочну` функцію — тобто враховуватиметься на етапі перевірки набору, але ігноруватиметься на етапі застосування.

Для кошика та позицій алгоритм перевірки трохи відрізнятиметься.

###### Набір для кошика
1) Усі вказані знижки кошика мають бути доступні для кошика.
2) Кожна з указаних знижок позиції має бути доступна хоча б в одній із позицій кошика.

###### Набір для позиції
1) Усі вказані знижки позиції мають бути доступні для конкретної позиції (памʼятаємо, що для кожної позиції пошук
відповідного набору відбувається незалежно — шляхом перебору від першого до останнього. І за різних доступних знижок для
кожної позиції може бути застосований різний набір).
2) Усі вказані знижки кошика мають бути доступні для кошика.

#### 2.1.2. Робота зі знижками в замовленні

На сторінці роботи із замовленням є можливість змінювати параметри створених знижок, змінювати черговість застосування,
видаляти знижки або додавати нові. Під час збереження зміненого замовлення відбудеться перерахунок вартості замовлення з урахуванням
змінених знижок.

### 2.2. Сайт

На сторінці кошика та у спливаючому кошику відображаються доступні для користувача знижки за умови, що виконується
хоча б один набір знижок. Саме знижки з цього набору будуть видимі користувачу та згодом використані під час
оформлення замовлення. Користувач не має можливості напряму впливати на вибір якогось набору, дізнатися, який набір був
застосований, змінювати набір або отримувати інформацію про інші можливі набори. Після оформлення замовлення користувач
зможе бачити застосовані знижки на сторінці замовлення.

## 3. Створення власних знижок у системі

Під час розробки модуля в систему можна додавати власні знижки, які потім можна буде налаштовувати через сторінку
керування знижками.

## 3.1. Реєстрація знака знижки

Попередньо знижку потрібно зареєструвати в системі. Реєстрація відбувається через виклик методів
[registerPurchaseDiscountSign()](./modules/init.md#registerPurchaseDiscountSign) (для позиції) або
[registerCartDiscountSign()](./modules/init.md#registerCartDiscountSign) (для кошика) в методі `init()` класу
[Init](./modules/init.md).
Потрібно вказати знак знижки, назву та опис для сторінки керування знижками. Назва й опис мають задаватися
через мовну змінну у файлах перекладів. Для цього у файлах backend-перекладів створіть новий переклад, а його
назву використайте як назву знижки під час реєстрації.

*Приклад 7:*

```php
//backend/lang/ua.php:
$lang['discount_coupon_name'] = 'Купон';
$lang['discount_coupon_description'] = 'Купон, який користувач вводить у кошику.';
```

```php
class Init extends AbstractInit {
    public function init()
    {
        //...abstract 
        $this->registerCartDiscountSign(
            'ok_coup',
            'discount_coupon_name',
            'discount_coupon_description'
        );
        //...abstract 
    }
}
```

Також реєстрацію можна виконувати в будь-якому місці, використовуючи методи `registerPurchaseSign()` і `registerCartSign()` класу
`Discounts.php`

## 3.2. Додавання знижки

Щоб знижка була доступна і міг бути застосований набір, який її містить, її потрібно додати або в сам кошик,
або в конкретну позицію — через використання властивості `availableDiscounts` і додавання в цей масив, використовуючи як ключ
знак знижки. Додавання має відбуватися через розширення методу `attachDiscounts()` класу `Okay/Core/Cart.php`.

Знижка має бути обʼєктом класу [Discount](./core/Discount.md).

Обовʼязковими для вказання є властивості `sign`, `value` і `type` (absolute — абсолютна, percent — відсоткова).

Опціональною є властивість `fromLastDiscount`. Якщо не задано, враховуватиметься те, що написано в `наборі`.

Властивості `name` і `description` — мовні змінні, які беруться з frontend-перекладів. Ці значення перекладів
будуть збережені в базу і будуть мультимовними. Якщо не задані — беруться змінні, вказані під час реєстрації знака знижки.
УВАГА! Беруться лише змінні, а не самі переклади. Це означає, що якщо під час реєстрації було вказано назву перекладу
`discount_coupon_name`, а потім її не перевизначили в момент додавання знижки, то переклад із такою ж назвою буде шукатися
у frontend-перекладах. Це дозволяє не дублювати код, якщо переклади назви та/або опису мають однакові назви на backend і frontend.\
Оскільки переклади — це статичні дані, є можливість додати в них динамічні. Для цього в перекладі
(обовʼязково рядок в одинарних лапках) потрібно вказати змінну у форматі `{$coupon}`, а у `discount` у масив `langParts` додати
елемент, ключем якого буде ця змінна, а значення визначатиметься динамічно.

У Прикладі 8 ми створили переклади для backend і frontend. Зареєстрували знижку для кошика в методі `init()`, додали extension
для методу `attachDiscounts`, і в `FrontendExtender` додали в кошик нашу знижку. Тепер, якщо набір, який
використовує, наприклад, лише цю знижку, отримає найвищий пріоритет — ця знижка буде застосована до кошика.

*Приклад 8:*

```php
//backend/lang/ua.php:

$lang['discount_coupon_name'] = 'Купон';
$lang['discount_coupon_description'] = 'Купон, який користувач вводить у кошику.';
```
```php
//design/okay_shop/lang/ua.php:

$lang['discount_coupon_name'] = 'Купон';
$lang['discount_coupon_description'] = 'Назва купона {$coupon}';
```
```php
class Init extends AbstractInit {
    public function init()
    {
        //...abstract 
        $this->registerCartDiscountSign(
            'ok_coup',
            'discount_coupon_name',
            'discount_coupon_description'
        );
        
        $this->registerChainExtension(
            [Cart::class, 'attachDiscounts'],
            [FrontendExtender::class, 'attachDiscounts']
        );
        //...abstract 
    }
}
```
```php
class FrontendExtender implements ExtensionInterface
{

    //...abstract 
    public function attachDiscounts($cart)
    {
        $discount = new Discount();
        $discount->sign = 'ok_coup';
        $discount->type = 'absolute';
        $discount->value = 100;
        $discount->langParts['coupon'] = $_SESSION['coupon_code'];
        $cart->availableDiscounts['ok_coup'] = $discount;
    
        return $cart;
    }
    //...abstract 
}
```
